# 00919 雲端與資料更新備忘

## 第一版原則

- 先維持「按一下更新資料 / 跑報表」的流程，跟兩倍大盤專案一致。
- 不把第一版核心流程壓在 Google Apps Script 上，避免個人 Google 帳號遇到 Drive、OAuth、Web App 權限限制。
- 可以把專案資料夾放在 Google Drive、OneDrive 或其他同步資料夾，但抓資料動作先由本機執行。
- 日後若要完全雲端自動跑，再評估 GitHub Actions、小型雲端主機，或權限確認後的 Apps Script。

## 資料檔分工

- `data/monthly_history.json`：長期累積市場月資料，例如月均價、月底價、AUM、受益人數、淨值與折溢價。
- `data/trades.json`：人工輸入交易紀錄。
- `data/dashboard_data.json`：每次抓取後給儀表板讀取的整合資料。
- 個人持股、成本、累積配息、含息報酬不固定寫死在月資料累積檔，應由交易紀錄與配息資料即時計算。

## 雲端版方向

- 優先方案：雲端同步資料夾 + 本機按鈕更新。
- 進階方案：雲端頁面提供「更新資料」按鈕，背後由可執行 Python 或等效抓取程式的服務處理。
- 不建議第一版：純 Google Drive 靜態網頁直接自動抓資料，因為瀏覽器與 Google 權限限制較多。
